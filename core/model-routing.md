# 模型与推理等级调度契约（可选启用）

本契约只在产品已明确采用并提供模型路由锁时生效。它不改变角色身份、Profile审批、阶段状态、写入权限、质量标准或最终验收权。未采用时维持原有运行方式，不因升级基座而替已有项目选模型。采用后，本任务用户授权覆盖按锁进行有界串行委派；不需逐次重问。它不代表授权并行 worktree、阶段审批或阶段迁移。

## 角色启动与任务分配

1. 完成原有Profile、active_role/active_agent及上游批准检查，再读取指定的路由锁；不得以模型选择代替角色激活。Quick 使用其任务级范围授权，不虚构活动阶段角色。
2. 主协调者对可独立交付的工作项先分类，记录 `task_id`、类别、`risk_reason`，按“阶段/角色默认 → 任务类别 → 风险下限 → 失败升级”解析并补上档位与执行回执。共同输入与验收的小改动可合为一项，不为每次读文件或工具调用启动代理。当前角色按自身档位完成判断；已明确可交付的执行项按分类实际分派，不能仅因主角色更强就全部留给主角色。普通编码必须已有明确输入、写入范围和验收条件；否则交强档做澄清/计划。收到有界任务包的执行者直接执行，不重新协调或递归分派。
3. 用 models/codex-balanced.json 的语义档位引用模型，不在每个角色Prompt里复制模型名。具体model和reasoning effort必须与当前运行时model/list相容。
4. `coding`、`unit-tests`、`mechanical`、`initial-fix`、`documentation` 用 economy；`plan`、`test-design`、`code-review` 用 strong。`document-plan` / `document-review` 用 strong，适用于所有原阶段；`archive-execution` 用 tool，适用于所有原阶段。未列出的任务保留锁中定义。产品与架构的新决定保持责任角色的 frontier 档，不能包装成文档整理降档。普通明确整理可直接由 economy 执行；复杂压缩由 strong 先确定保留 ID、约束、版本、否定条件和遗留项，economy 整理，工具作静态校验，strong 语义复核。简单明确的小整理不强制四轮。
5. 身份/权限、密码/密钥、账务、数据丢失、迁移、并发、缓存和SSR跨层状态问题不得仅因文件少而标为普通任务：至少high；不确定且后果严重时critical。风险由责任角色依据任务与证据标注，程序不冒充语义审查器。
6. 当前默认每两个有证据的实现失败尝试提升一档，失败8次停止并交人工诊断；先应用风险下限。环境权限/依赖故障不计入实现失败。工具不自行判断业务成功、不自动重试。
7. command成功只代表执行结果，不等于测试覆盖正确或验收通过。测试设计和独立质量判断仍由strong/frontier承担，写实现的低成本执行者不能自行最终验收。

## 运行时边界

- 原生委派使用 `agt-models dispatch --project DIR --lock FILE --packet FILE --task T [--quick QID --role ROLE]` 解析策略、预检能力、登记待执行尝试并返回 spawn 参数；协调者须实际调用宿主 spawn，再登记结果，不能把返回参数当成执行完成。CLI 执行使用 `launch` 命令与相同参数，加 `--run`；不加时仅预览。运行后用 `record --project DIR --task-id ID --receipt FILE` 登记，用 `status --project DIR --task-id ID` 查看。每项并入现有计划，不另建重复计划。
- 任务包含 `task_id` 与 `risk_reason`，并保留 `objective`、`inputs`、`write_scope`、`acceptance`、`risk`、`prior_attempts`。每个子任务 fork 最小上下文（`fork_turns: none`），不让执行者自行递归分派；主协调者统筹预算。默认串行，不默认建立并行 worktree。
- 分派失败或模型不具备所需能力时，记录阻塞；只有具备明确来源的串行例外才可继续，并记录例外，不得将其说成已分档执行。运行时未知字段及 usage 原样记 unknown；exit 0 不是验收通过。

- Codex CLI通过新会话显式传--model和model_reasoning_effort；它不会改变已打开App聊天的主模型。
- 若宿主提供支持模型覆写的子任务调用，由责任协调者传入解析后的model/effort、最小任务上下文与限定写入范围。不能用“角色名”假装切换模型。
- 无宿主切换能力时，给出选择结果，交用户切换或通过CLI启动。必须区分requested_model、运行时确认的actual_model和unknown；没有证据不能声称实际已换模。
- model/list失败、模型不可用、推理等级不支持时明确阻塞；不静默使用更贵、能力不足或未知模型。
- 模型、路由锁和任务包不授予新权限，不绕过审批、sandbox或原有Skills。执行器只调用现有Skill，不复制/削弱角色契约。

## 控制上下文与成本

- 阶段主模型负责判断与计划，不把整段历史复制给执行者；任务包只包含目标、批准输入路径、限定写入范围、验收和风险。
- 按共同契约的[上下文读取](./role-contract.md#context-reading)加载：完整读取当前Skill、继承契约和角色定义；产物模板按需读取，上游按稳定ID/章节定位并完整读取适用约定及依赖，不因任务包漏列就删掉关键限制。历史按需检索，链接不自动递归展开。
- 测试/构建输出落证据文件；上送命令、退出码、失败摘要与证据路径。不反复上送完整日志或复制旧报告全文。
- 同一失败必须携带已试方法和结果，避免换模型后从头重复。环境故障与实现失败分开计数。
- 成本按“完成一个被验收任务的总消耗”衡量，包含主代理、子任务、重试、验证和返工。没有运行时usage就标unknown，不能拿字数当token或将API标价当Codex订阅扣费。
- 当前实现提供分档、元数据预检、持久化尝试与失败升级、运行证据及可观测的会话 usage；不提供账单级预算熔断、全局token硬上限或后台守护进程。单个子会话 usage 不含未观测的主代理和其他会话消耗。
- 任务包的输入列表是定位入口，不是强制读取白名单；当前CLI适配器不拦截模型的文件读取。静态文件计量也不代表已观测的运行时输入。需要整理时按[整理与归档协议](./document-maintenance.md)核对证据和遗留项。

## Codex模型更新

每次模型 launch、dispatch 和 check-updates 均重新查询当前Codex模型清单，检测CLI版本、新增/移除模型、effort变化和官方upgrade提示。纯工具任务不查询模型。不做定时后台请求，能力发现本身不创建模型推理turn。

发现变化后生成可审阅差异；现有锁保持不变。推荐升级仅是候选，先核实官方可用性/能力/成本，再在固定代表任务中比较通过率、返工次数和总用量。确认后更新中央policy并生成新的版本化锁；旧锁留作回滚和历史追踪。不能仅按版本号/模型名排序决定最强或最便宜，也不能把“有upgrade字段”当作质量等价承诺。

具体命令与能力边界见 [Codex适配器](../adapters/codex/README.md)。
