# 模型与推理等级调度契约（可选启用）

本契约只在产品已明确采用并提供模型路由锁时生效。它不改变角色身份、Profile审批、阶段状态、写入权限、质量标准或最终验收权。未采用时维持原有运行方式，不因升级基座而替已有项目选模型。

## 角色启动与任务分配

1. 完成原有Profile、active_role/active_agent及上游批准检查，再读取指定的路由锁；不得以模型选择代替角色激活。
2. 按“阶段/角色默认 → 任务类别 → 风险下限 → 失败升级”解析。普通编码必须已经有明确输入、写入范围和验收条件；否则先交强模型澄清/Plan。
3. 用 models/codex-balanced.json 的语义档位引用模型，不在每个角色Prompt里复制模型名。具体model和reasoning effort必须与当前运行时model/list相容。
4. 钱花在判断上：产品/架构用frontier；实施计划、设计判断、评审/验收用strong；明确的编码、测试样例与文档整理用economy；纯命令交工具。
5. 身份/权限、密码/密钥、账务、数据丢失、迁移、并发、缓存和SSR跨层状态问题不得仅因文件少而标为普通任务：至少high；不确定且后果严重时critical。风险由责任角色依据任务与证据标注，程序不冒充语义审查器。
6. 当前默认每两个失败尝试提升一档，失败8次停止并交人工诊断。失败是同一任务的有证据失败次数，由调用方传入；工具不自行判断业务成功、不自动重试，也不把环境权限/依赖问题无限升级成模型消耗。
7. command成功只代表执行结果，不等于测试覆盖正确或验收通过。测试设计和独立质量判断仍由strong/frontier承担，写实现的低成本执行者不能自行最终验收。

## 运行时边界

- Codex CLI通过新会话显式传--model和model_reasoning_effort；它不会改变已打开App聊天的主模型。
- 若宿主提供支持模型覆写的子任务调用，可由获得委派授权的责任角色传入解析后的model/effort、最小任务上下文与同一角色范围。不能用“角色名”假装切换模型；本适配器不自动派生子代理。
- 无宿主切换能力时，给出选择结果，交用户切换或通过CLI启动。必须区分requested_model、运行时确认的actual_model和unknown；没有证据不能声称实际已换模。
- model/list失败、模型不可用、推理等级不支持时明确阻塞；不静默使用更贵、能力不足或未知模型。
- 模型、路由锁和任务包不授予新权限，不绕过审批、sandbox或原有Skills。执行器只调用现有Skill，不复制/削弱角色契约。

## 控制上下文与成本

- 阶段主模型负责判断与计划，不把整段历史复制给执行者；任务包只包含目标、批准输入路径、限定写入范围、验收和风险。
- 按共同契约的[上下文读取](./role-contract.md#context-reading)加载：完整读取当前Skill、继承契约和角色定义；产物模板按需读取，上游按稳定ID/章节定位并完整读取适用约定及依赖，不因任务包漏列就删掉关键限制。历史按需检索，链接不自动递归展开。
- 测试/构建输出落证据文件；上送命令、退出码、失败摘要与证据路径。不反复上送完整日志或复制旧报告全文。
- 同一失败必须携带已试方法和结果，避免换模型后从头重复。环境故障与实现失败分开计数。
- 成本按“完成一个被验收任务的总消耗”衡量，包含主代理、子任务、重试、验证和返工。没有运行时usage就标unknown，不能拿字数当token或将API标价当Codex订阅扣费。
- 当前实现提供分档/升级建议/元数据预检，不提供账单级预算熔断、全局token硬上限或后台守护进程。
- 任务包的输入列表是定位入口，不是强制读取白名单；当前CLI适配器不拦截模型的文件读取。静态文件计量也不代表已观测的运行时输入。需要整理时按[整理与归档协议](./document-maintenance.md)核对证据和遗留项。

## Codex模型更新

每次CLI launch和check-updates均重新查询当前Codex模型清单，检测CLI版本、新增/移除模型、effort变化和官方upgrade提示。不做定时后台请求，也不创建模型推理turn。

发现变化后生成可审阅差异；现有锁保持不变。推荐升级仅是候选，先核实官方可用性/能力/成本，再在固定代表任务中比较通过率、返工次数和总用量。确认后更新中央policy并生成新的版本化锁；旧锁留作回滚和历史追踪。不能仅按版本号/模型名排序决定最强或最便宜，也不能把“有upgrade字段”当作质量等价承诺。

具体命令与能力边界见 [Codex适配器](../adapters/codex/README.md)。
