# 文档整理与归档协议

仅在阶段验证完成、上下文超预算或需要整理历史时读取。目标是减少下次任务需要读取的内容，同时保留可执行的需求、约束和未完成事项。日常读取遵循[共同契约](./role-contract.md#context-reading)。

## 0. 以接续开发的 agent 为使用者

保留标准是信息能否帮助后续 agent 恢复任务、遵守约束、找到实现、选择验证和避免已知错误；不以人工汇报完整、文件数量或摘要越短越好作为目标。里程碑结束后，当前交接改为已交付基线与遗留事项入口，移除已经完成的“等待审阅/交接/收尾”下一步；保留正式状态来源，不由整理启动下一里程碑。

- **最新有效知识**：当前规则及原因、适用条件、例外、尚未验证事项和任务入口。测试保留逐能力的适用版本、方法、结果与未覆盖范围，不用最后一次测试覆盖全部历史结论。
- **可复用失败经验**：按“触发条件 → 有证据的原因 → 已验证处理 → 回归入口”提取；推测和未验证修复明确标记。重复过程退出默认读取，影响判断的原件仍可定位。每个条目应来自原始来源的增量修订，避免摘要反复压缩。
- **实验资料**：产品中的模型评测与开发 agent 的工作流实验分别记录。模型样本成功不能证明交接有效；静态入口检查不能证明新会话 agent 能完成任务。必要的失败轨迹/对照样本按实验目的保留，不把全部工具输出装入启动上下文。
- **归属**：产品约束、代码入口和具体失败事实留在产品；可跨项目复用的方法融入基座现有提示词，同一规则只维护一处。流程修复不默认新增复盘报告、案例库或复制产品证据；单项目观察不能自动提升为全局规则。
- **组织**：复用当前状态和角色交接作小入口，按任务读取权威正文，按稳定 ID 查历史。Git 已保存完整原文时，索引记录完整 commit、原路径和摘要即可，不重复复制整个历史；未提交的唯一原件仍须先保存快照。链接多不代表应递归读取。

调研按目的使用：[长期 agent 开发实践](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)用于状态恢复与完成判定；[上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)用于按需读取；[ACE 研究](https://arxiv.org/abs/2510.04618)用于避免过度压缩和反复改写丢失知识。这些是设计依据，不是本工作流已经获得同等效果的证明。架构决策记录可借鉴原因/条件，Git 和产物存储只解决追溯，均不能代替 agent 接续效果的验证。

## 1. 选择一个批次

- 普通修订和交接前就地去重；阶段验证完成后整理该阶段，跨阶段依赖只纳入必要关联。里程碑结束时检查跨阶段重复决策、过期约束和遗留任务，不重新总结全部归档。
- 入口或任务 planning 超出共同契约的软预算时，在安全检查点整理；没有 tokenizer 时可依据同口径字符增长、重复正文或恢复困难触发，不能把字符阈值冒充 token 阈值。
- 先看当前状态、索引、文件清单及受影响文件的工作区修改。只整理本角色有权维护的文档；无法归属的修改或并发写入先跳过并注明，不用 reset/clean/stash 清理工作区。写回前复核文件是否已被他人更新。
- 复用 Profile 必需路径和已有计划/决策/交接入口。维护协议留在基座；不向产品复制一套 COMPACT、STATE、ROADMAP。业务代码、部署和外部写操作不属于整理范围，不自动提交或推送 Git。

## 2. 核实事项与证据

按稳定 ID 区分以下状态，沿用产品等价字段即可，不替换工作流状态机：

| 事项状态 | 处理 |
|---|---|
| planned / in_progress / blocked | 保留未完成目标、依赖、验收和解除条件 |
| implemented_unverified | 保留未验证项、所需验证及实施上下文 |
| verified | 证据与验收范围匹配后，才可移除活动计划中的完成步骤 |
| cancelled / superseded | 有明确取消或替代依据；保留来源和替代 ID，不写成完成 |

归档是保存位置，不是成功状态。未验证事项的旧稿可以保存为历史，但当前入口必须保留其未完成任务；整份混合状态计划不能因部分通过就退出活动范围。设计等非代码阶段使用获批准的产物版本和对应检查记录，不强行要求代码测试。

验证证据至少能定位：事项/验收 ID、代码或产物版本、影响结论的工作区修改、检查方式或命令、实际结果、未覆盖范围和原件。无 commit 时记录可恢复快照及内容摘要；无法建立对应关系时标未验证。匹配目标版本且相关内容未变化的既有证据可复用，不机械重跑全部测试。文件存在、计划打勾、代码合并或命令退出 0 都不能单独证明验收完成。

局部修订的完整性检查围绕当前交付清单、变更及相关依赖/引用；复用已冻结基线，只保存本轮需替换的唯一原件，不因一次小改动反复复制、读取或重新摘要全部历史文件。当前交付仍须能追溯到实际源与环境；依赖不明、发现漂移或整体交付要求全量核对时扩大范围并说明原因。既有冻结清单和已批准校验要求不能静默缩减，复用要记录适用版本及未受影响的依据。

## 3. 按条目增量收敛

- 整理前列出本批次未完成 ID、有效约束与决策；在原有计划/交接中核对整理后的去向，不另建一套任务清单。每个遗留项保留验收、来源、必要复现信息和下一步。
- 当前状态/阻塞/下一动作进入当前交接；任务与验收留在对应计划或 CR；长期决策留在责任角色主文档或决策条目，入口只列相关 ID 和链接。
- 按 ID 更新权威正文，不反复把摘要再摘要。保留原因、适用版本、否定条件、例外、未知项，以及可能影响未来判断的被否决方案。歧义回查原文，冲突保留并交责任角色处理。
- 实现细节可从活动摘要移除并指向代码；有效需求与实现不符时记录为差异或待办，不能把应然改成现状。过期决策标明替代条目，不能静默覆盖已冻结决定。

## 4. 保存原文并建立检索入口

- 替换已批准版本前确认存在可恢复的提交或冻结副本；没有可靠历史先留快照。唯一原始记录不能由有损摘要替代。原始审批、失败、测试证据及受摘要约束的原件不可改写。
- 先提取有效约束和未完成事项，再归档已验证完成或明确被替代/取消的材料。正式历史保留可恢复原件；临时测试产物按下述用途清理，不默认永久保存所有截图。
- 复用已有历史索引；没有时在本角色允许路径下建立一个索引，或在当前交接维护少量索引行。仅索引本批次，不要求扫描全库。每项包含：事项/阶段 ID、原路径与保存路径、真实状态、代码/产物版本及证据位置、提取出的决策与遗留任务 ID。原地保留时两路径相同。
- 检查稳定 ID、入链、相对路径、锚点和冻结摘要引用。移出受引用原件前必须补齐版本解析和恢复入口；仍被当前任务或自动检查直接读取的文件先保留，或同步迁移消费者。不确定兼容性时原地保存。当前入口仍须指向有效决策与授权，不把历史保存视为撤销授权。

### 4.1 测试图片与运行产物的保留

保存截图、送图判断、提交正式证据是三个独立动作。截图生成不等于需要进入 Git；下表同样适用于录屏、trace 和测试报告附件。

| 用途 | 默认处理 |
|---|---|
| 日常成功截图、排查过程、重复重试、临时 diff | 输出到 Git 忽略的临时目录或测试框架产物目录；相关诊断/复验结束后清理，不逐轮提交或复制到文档库 |
| 未解决问题、未完成评审所必需的图片 | 保留足以接续的证据，关联问题、版本和状态；问题关闭或被替代后重新判断用途 |
| 正式验收必要代表图、批准的视觉回归基线 | 精选提交，关联验收、版本与环境；不同记录复用同一原件，运行测试不得覆盖冻结证据或自动接受新基线 |
| 已被替代的历史测试图片 | 有可靠版本原件且当前无直接使用依赖时，可在授权整理范围内移出工作树，保留检索与恢复入口；不因“曾是证据”要求永远留在当前目录 |

- 报告长期保留事项/验收 ID、版本、方法、实际结果、未覆盖项和回归入口。图片按证明价值保留；删除临时图片不能抹去失败事实、把未验证改成通过或替代仍需图片证明的结论。
- 采集前确定输出目录与用途。先使用项目已有的忽略目录；正式证据由报告维护者按需挑选，普通测试不能默认写入冻结 `.planning/.../evidence`。不要用全局 `*.png` 忽略规则误伤设计资源、夹具或回归基线。
- 批量移除已提交图片前，核对工作区内容与可恢复 Git 原件一致，排除未提交/他人修改、当前设计资源、测试输入、未决事项及当前评审所需文件。已有用户清理指令覆盖这一可逆整理，无需重复确认。
- 在已有历史索引或本批恢复清单记录完整 commit、原路径、内容摘要和恢复命令；逐文件校验恢复字节。当前报告链接到该入口，历史报告/哈希清单按原版本解析，不重算旧清单、批量改写旧结论或用新图覆盖旧图。仅给出 Git 提交但没有检索方法不算可追溯。
- 无可靠原件、用途不明或消费者仍依赖原路径时先保留。明确区分工作树减量与 Git 历史体积；常规整理不重写 Git 历史、不自动提交或推送，不为删除图片再制作整库备份。

## 5. 验收与交接

在现有交接的整理栏记录以下结果；普通无实质变化的整理不增加整套报告：

1. 未完成事项逐 ID 有去向，验收、有效约束及其原因保留；所有完成声明有匹配证据，未知仍可见。
2. 当前入口、相关契约、证据与历史引用可用；原件可恢复，未覆盖他人修改。
3. 同一批次再次检查时不新增重复条目、快照或纯时间戳改写；只有内容实际变化才更新。
4. 用相同任务、角色和计量方式对比默认启动范围及任务补充范围，记录文件/章节、前后大小、超预算原因。历史存储总量与实际读取量分开；同一文件去重后的静态大小不等于运行时累计输入或计费 tokens。

可用 `node validators/measure-context.mjs -- <明确选定的文件...>` 在基座目录分别计量各类输入；不传整个目录。它只测完整文件的 Unicode 字符数/UTF-8 字节数，tokens 与运行时输入未知；若实际只读章节，应记录真实片段及范围，不能将整文件数值当成片段用量。

首次试点、改变入口结构或大幅整理后，做一次不依赖旧聊天的新会话交接测试：仅提供任务、基座入口和产品位置，让接手者按读取协议回答“当前阶段、下一步具体动作及完成条件、不可破坏的约束、未验证事项、追溯位置”，每项附来源。接手者可按需检索，不预先给答案或全量历史。检查是否误用过期结论及实际读取范围，缺失时补对应入口。

测试使用只读会话；不自行派生子代理或启动付费推理。没有独立会话条件时可先做静态追踪，明确记录“新会话交接测试未执行”，不能把自检称为独立通过。交接测试不批准产品、不触发阶段迁移；未执行的试点测试保留为待验证项，不额外阻塞无关的已授权工作。

检查失败时保留原文与活动事项，不宣称归档验收通过。未解决的语义问题交责任角色，阶段权限沿用现有守门流程。

## 6. 上下文压缩的执行编排

用户要求“压缩、归档、整理测试或修改记录”时，默认目标是语义收敛与减少任务读取量。文件打包只解决备份，压缩包大小、目录体积、文件数不能作为上下文压缩成果。先在现有交接声明本批文档和代表任务；范围不能自行缩为 state/project/agents 等入口文件。

### 责任与顺序

当前执行者在现有交接维护一张简短责任表：责任范围、当前入口、需收敛的文档、原件来源、检查结果。单会话可在用户授权内按责任分区串行执行纯文档维护，注明实际执行者；不虚构角色运行或默认派生代理。跨角色的未确认语义仍回责任角色。

1. **确定基线**：核对当前状态、批准范围、变更 ID、保留事项和相关文档版本；记录可恢复的原件。只枚举本批文件，避免递归读历史。
2. **收敛专业正文**：产品/设计/架构维护当前约束与原因；实现按问题 ID 收敛最终修改及回归入口；QA 按能力收敛适用版本、有效证据与未验证边界。每个范围给出已整理或无需整理的依据，不能只由守门器改入口代替。
3. **收敛修改与验证入口**：将历史轮次退出默认读取。已接受、已替代、取消、未完成分别标注；原稿的 open/待审只代表当时状态。必须有后续批准来源，不能仅从里程碑 complete 推导每项测试通过或缺陷已修复。
4. **汇合当前交接**：专业正文完成后再更新状态入口与接续文档。守门器检查覆盖到的责任范围、遗留 ID 和授权来源，不代写新的专业结论。已完成里程碑按工作流的文档维护规则处理，不重开开发阶段。
5. **检查结果**：按下述任务验收；未完成的整理范围仍列待办，不以打包成功、链接齐全或应用已验收替代整理完成。

### 当前正文与历史原件

| 材料 | 当前正文保留 | 退出默认读取的内容 |
|---|---|---|
| 测试记录 | 能力/验收 ID、适用版本与环境、方法、有效结果、未覆盖项、回归入口、原件定位 | 每轮命令流水、重复重试过程、已被后续结果替代的临时结论 |
| 修改记录 | 问题 ID、最终行为、原因/约束、替代关系、代码与回归位置、当前处理依据 | 重复提交/审阅过程和失效下一步 |
| 失败经验 | 触发条件→有据原因→已验证处理→回归入口；未知明确保留 | 不影响再次诊断的过程复述 |
| 当前交接 | 已交付基线、有效政策、未完成项与明确接续动作 | 已完成的待审/待部署/待交接指令 |

冻结原件与可维护的当前正文分别处理。改写前记录原件的 commit、路径、摘要与必要锚点；冻结清单仍指向原版本，不重算旧清单来冒充未修改。当前路径改变含义时，补充版本解析与历史入口，保留已被引用的锚点或明确重定向；仅保留 Git 提交但不给检索方法不算可追溯。无可靠提交时只快照本批唯一原件，无需复制整份历史或生成 tar 包。未经明确授权不删除原件。

### 整理验收与效果验证

在现有交接区分三个结果，不能合写一个 PASS：

- **内容收敛**：责任表覆盖本批范围；当前正文无过期行动指令；有效约束、原因、否定条件与每个遗留 ID 都有去向。
- **静态完整性**：原文可按版本恢复，摘要、入链、锚点与证据边界核对；相同代表任务的输入文件/章节、去重字节与字符前后对比。新索引和必要补读计入分母；不只测变小的文件，也不把全部文件减少率冒称实际节省。
- **接续效果**：独立新会话根据任务自行定位来源，回答当前状态、下一动作、约束、未验证事项及证据；记录读到的范围、误用旧状态/遗漏与重复查找。未运行则记 NOT_RUN，不能声明效果已验证；这不撤销已有产品验收。

代表任务至少涵盖状态恢复、一次缺陷回归定位、一次未验证项识别；根据本批内容选具体题目。整理后再检查相同输入应无新增摘要、快照或时间戳改写。普通静态脚本只能检查可解析性、存在性与摘要，不能替代语义判断或独立接续测试。
