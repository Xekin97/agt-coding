# 并行实现 Worktree 计划

## 是否需要并行

- 任务之间是否真正独立：
- 并行带来的收益：
- 共享文件和冲突风险：
- 结论：单工作区 / Git worktree 并行。

## 工作树分配

| 任务 | 分支 | worktree 路径 | 文件责任边界 | 依赖 | 负责人语义名 |
|---|---|---|---|---|---|

## 合并顺序

1. 按依赖关系列出顺序；
2. 每次合并前需要通过的开发期检查；
3. 共享契约或公共组件发生变化时的处理方式。

## 合并检查

- 工作树无未识别或未保存改动；
- 差异符合批准方案和文件责任边界；
- 单元测试、lint、格式化、类型检查和适用构建通过；
- API、数据模型和共享组件不存在未批准变化；
- 冲突解决没有替用户做产品或架构决策。

## 清理条件

只有分支已经确认合并、验证证据已记录且工作树没有未保存内容时，才允许清理对应 worktree。
