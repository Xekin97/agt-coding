### 文案源编制说明（生成后移除）

在 `copy.json` 写实际产品的文案。顶层使用 `static`、`templates` 两个映射，值为字符串、键唯一，无内容的映射为 `{}`。下面只示范结构，不向产品引入生成能力：

```json
{
  "static": {
    "generation.submit.label": "开始生成",
    "generation.empty.title": "还没有生成内容"
  },
  "templates": {
    "generation.usage": "已使用 {used} / {limit} 次"
  }
}
```

原型与前端消费同一来源；按项目约定导入或生成资源，保持标点及明确的换行要求。真实业务数据和 AI 输出是变量，不固定为原型示例。若生成了工程副本，技术方案记录来源与转换方法，禁止另行手工维护。

## 详细规则入口

- 布局/样式：原型文件及相关区域，Token 引用 `theme.css`，不复制数值表。
- 状态与 Motion：`interactions.md` 中的条目；包含触发、反馈、起止、时长/缓动、中断、异常及即时切换的适用原因。
- 响应式与可访问性：`responsive-accessibility.md` 中的条目；包含目标视口、键盘/焦点与减少动效行为。
- 资源：实际图片/图标/字体路径及用途，标明缺失项，不能让前端自行找替代品。

## 实现约束与验收

| 验收 ID | 页面/区域/状态及来源、原型定位 | 必须保持的结果 | 允许差异/容差及依据 | 检查条件、方法与充分证据 |
|---|---|---|---|---|
| | | | | |

按页面使用局部 ID（如 `UIA-PAGE-001-01`）。明确文案键、位置、顺序和状态；区分文本/属性、布局数值、必要视觉对照及实际操作/计时，写清观察到什么才足够判定，不要求每条都截图。动态内容固定/遮罩引用具体来源，不能遮掉验收对象；容差不套统一数值。优先级不能作为省略已批准要求的理由。

前端在现有方案或验证报告中补对应运行区域的定位，复用本表 ID；原型与实现允许不同 DOM。文案和样式数值仍引用各自真源，不额外要求 `design-contract.json` 或逐元素 CSS 快照。旧产物有等价定位/验收信息即可使用，不因缺少新表格列而阻塞无关工作。

技术自由限定于批准方案内的组件、DOM 和实现手段，不允许重写固定文案、删减内容或改变设计结果。未定义之处列为待澄清，不让前端从冲突版本中自行拼选。

## 设计自检与未决项

- 浏览器实际检查：产物版本、视口/数据/状态、操作、结论和证据路径。
- 文案源、原型、资源、详细规则及验收条目的一致性：
- 设计质量是否满足本轮目标、剩余差异及影响：
- 未执行检查/缺失资源/待澄清定义：条目 ID、影响及补齐方法。
- 整改时的下游影响：受影响的前端方案、实现、测试预期和失效证据，链接现有任务/CR。
